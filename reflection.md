# 💭 Reflection: Game Glitch Investigator

Answer each question in 3 to 5 sentences. Be specific and honest about what actually happened while you worked. This is about your process, not trying to sound perfect.

## 1. What was broken when you started?

- What did the game look like the first time you ran it?
- List at least two concrete bugs you noticed at the start  
  (for example: "the hints were backwards").
  
When I first ran the game, the interface loaded correctly but several gameplay features were not working properly. The hint system sometimes returned the wrong message, so guesses that were higher or lower than the secret number did not always produce the correct “Too High” or “Too Low” feedback. The Show Hint option also failed to display the secret number when it was enabled. I also noticed that the difficulty level logic was not implemented properly, so the number range did not logically match the selected difficulty. In addition, the guess history did not reset when starting a new game, the attempts counter did not increase correctly, and the score tracking system was not counting wins properly.

- How did you decide whether a bug was really fixed?
- Describe at least one test you ran (manual or using pytest)  
  and what it showed you about your code.

I decided a bug was fixed by running the application and checking if the behavior matched the expected result after making the change.

One test I ran was checking the hint logic. I tested a case where the secret number was 50 and the guess was 60. The program correctly returned “Too High,” which confirmed that the comparison logic was working properly.

AI helped me understand how to design tests by suggesting simple test cases that compare a guess to the secret number and check if the correct message is returned. This helped me verify that the game logic was working correctly.

## 4. What did you learn about Streamlit and state?

- How would you explain Streamlit "reruns" and session state to a friend who has never used Streamlit?

Streamlit reruns mean that every time a user interacts with the app (for example pressing a button or entering a value), the entire script runs again from top to bottom. Because of this, variables would normally reset each time the app reruns.

Session state is used to store values so they don’t disappear during these reruns. It keeps important information such as the secret number, score, attempts, and guess history so the game can continue working correctly even when the app refreshes.

Next time I do a coding task with AI, I know I will be more cautious about applying the suggestions. AI can be a little helpful, but I know I need to be more thorough with my suggestions before applying them. I will be sure to test and think through the suggestion as the AI will not do the job for me.
